# PRD：Workbench 视觉体验 2.0（增量版）

- 版本：v0.5.0 → 目标 v0.6.0 ｜ 日期：2026-11-03 ｜ 作者：产品（许清楚）
- 性质：纯增量 PRD，只描述变更。现有"精密仪器"设计语言、主题系统、玻璃材质等基础能力不复述。

## 1. 产品目标

1. 让"监控工作台"有可感知的质感与生命感：动效、深度、氛围三线升级，且不牺牲性能与无障碍。
2. 把主题个性化从"选颜色"升级为"定氛围"：渐变强调色 + 氛围强度 + 翻倍的主题库。
3. 全部改动只用 transform/opacity 合成层动画、全部用色过 AA，保持现有质量门禁不回退。

## 2. 用户故事

| # | 故事 |
|---|---|
| U1 | 作为重度用户，我想把动效强度调为"关/标准/满格"，以便在低配机或专注模式下控制动态干扰。 |
| U2 | 作为个性化爱好者，我想给主题配渐变强调色和 0-100 的氛围强度，让界面有"我的气质"而非统一模板脸。 |
| U3 | 作为长时间盯盘的运维，我希望卡片有真实深度、hover 微抬升，一眼分清哪块信息在"浮"在上面。 |
| U4 | 作为新用户，我想在统计卡上看到渐变大数字和图标底座，首次打开有 3 步引导告诉我这工具能干什么。 |
| U5 | 作为多平台用户，我希望在 Windows/macOS/Linux 上动效都流畅不掉帧、无闪烁。 |

## 3. 需求池

### P0（本期必做）

| ID | 需求 | 说明 | 可实现性 |
|----|------|------|----------|
| P0-1 | 动效系统 | 视图切换过渡、卡片/按钮 hover 微交互、统计数字 count-up、骨架屏 shimmer；全部仅用 transform/opacity（GPU 合成）；新增"动效强度"三档设置（关/标准/满格）；`prefers-reduced-motion` 时自动降为"关"并允许覆盖 | 【已验证可行】现有 rise-in 已走 opacity 路径，扩展为全局 motion token 即可 |
| P0-2 | 卡片深度系统 | 移除全局 `--shadow-card: none`；每主题可配 elevation（层级 0-3）与 shadow 参数；暗色主题用低透明大阴影+描边补偿；hover 微抬升（translateY -2px + shadow 过渡） | 【已验证可行】主题 token 已由 applyTheme 写入 html 变量，新增 token 无架构改动 |
| P0-3 | 渐变强调色 | 新增 `accent2` token + 主题级"渐变开关"；accent→accent2 渐变应用于主按钮、选中态、统计数字；所有新用色组合过现有 WCAG AA 求解器门禁 | 【已验证可行】AA 求解器已在 e2e 门禁中 |
| P0-4 | 内置主题 8→16 | 新增 8 套有性格主题（建议）：`midnight-aurora`（深蓝绿极光）、`ember`（暗红炭火）、`matcha`（暗绿抹茶）、`grape-soda`（紫罗兰）、`paper`（暖纸米白）、`nordic-light`（冷灰蓝亮）、`sakura`（淡粉亮色）、`mono-brutal`（黑白高对比）；全部 4 暗 4 亮方向、过 AA | 【已验证可行】主题编辑器与分享链接机制已支持任意 token 组合，纯数据新增 |
| P0-5 | 统计卡视觉重做 | 图标加 accent-soft 圆角底座（锚点）、数字用 accent 渐变+tabular-nums、卡 hover 有反馈；保持信息密度不降 | 【已验证可行】纯组件级改动 |
| P0-6 | 氛围强度参数 | glow 从玻璃材质专属改为主题参数 glow 0-100（0=关）；非玻璃主题也可有光晕；实现走 box-shadow/opacity，不引入额外 GPU 大图层 | 【已验证可行】现有光晕实现可参数化 |
| P0-7 | 首次启动 3 步引导 | 3 步浮层（功能一览→主题选择→完成）；可随时跳过；`localStorage` 记忆不再弹出；尊重"关"档动效 | 【已验证可行】纯前端浮层 |

### P1（应做，含风险）

| ID | 需求 | 说明 | 风险 |
|----|------|------|------|
| P1-1 | 空状态插画 | 内联 SVG 插画替代纯文字空态 | 插画风格需与"精密仪器"语言一致，易违和 |
| P1-2 | 自定义背景图 | 用户选本地图片做工作台背景（低透明+暗化处理） | 大图内存、亮色主题可读性；需压缩与对比度复核 |
| P1-3 | 图表动效细化 | ECharts 切换数据时过渡动画统一节奏 | ECharts 动画与 reduced-motion 策略需逐图核对 |
| P1-4 | 主题包导出增强 | 分享链接附带渐变/氛围参数 | 旧链接兼容需迁移逻辑 |

### P2（可做）

| ID | 需求 | 风险 |
|----|------|------|
| P2-1 | 统计卡 hover 展开迷你趋势 sparkline | 增加渲染负担，需虚拟化或懒加载 |
| P2-2 | 主题随机"手气"按钮 | 与引导流程重复度高 |
| P2-3 | 卡片入场 stagger 编排 | 动画时长叠加易超时，需门禁上限 |

### 边界外（明确不做）

| 项 | 理由【边界外】 |
|----|----------------|
| 用户自由 CSS 注入 | 安全面：任意 CSS 可导致界面破坏与潜在攻击面 |
| WebGL 粒子背景 | 监控工具本身吃 GPU，与本产品定位冲突 |
| 云端主题市场 | 违背本地优先原则 |
| 移动端适配 | 桌面产品定位 |
| 声音特效 | 无必要，且干扰监控场景 |

## 4. 待确认问题（→ 交付总监）

1. 动效强度默认档位建议"标准"（非"满格"），是否同意？影响首启第一印象 vs 性能保守的取舍。
2. 新 8 套主题命名/配色方向是否照单采纳，还是先做 4 套灰度验证 AA 覆盖率？
3. 渐变开关默认值：默认开（更"2.0"但改变现有用户视觉）还是默认关（保守）？

## 5. 非目标

- 不做 CSS 注入、WebGL/粒子背景、云端主题市场、移动端、声音（见上表）。
- 不重构主题系统架构、不改后端/Rust 侧、不引入新运行时依赖（动画纯 CSS/token 实现）。
- 不改变现有信息架构与页面结构，视觉升级不迁移任何功能入口。

## 6. 验收要点

- 动效全部 transform/opacity，DevTools 无 layout thrash；reduced-motion 生效时 0 动画。
- 全部新增颜色组合通过 AA 对比度门禁；jscpd <3%、ESLint 零警告、441+ 前端单测与 136 Rust 测试保持绿。
- 暗色主题下卡片与背景层次可用肉眼区分（elevation ≥1 时）。
- 首次引导跳过后永久不再出现；三档动效设置即时生效并持久化。
